# Правила, задачи и алгоритмы

[Примеры](command-examples.md) · [Команды](../06_CLI_Reference.md) · [Сеть](../04_Mesh_Network_and_Data_Routing.md)

## Три способа описать действие

| Инструмент | Когда полезен | Пример |
|---|---|---|
| Правило | Действие зависит от показания | Если кнопка нажата, включить индикатор. |
| Периодическая задача | Действие нужно через интервал | Периодически выполнить диагностическую команду. |
| Алгоритм | Нужна последовательность | Проверить условия, выполнить действие, выдержать паузу, выполнить следующее. |

Настройка этих инструментов не требует доступа к исходникам прошивки.

## Правило

Правило связывает источник данных, условие и действие. Для первого знакомства используйте `rule_wizard`; для воспроизводимого стенда — [готовый пример](command-examples.md).

Базовый формат:

```text
rule_add <id> "<название>" <источник> <условие> <значение> <действие> <цель> [данные]
```

Простые численные сравнения: `>`, `>=`, `<`, `<=`, `==`, `!=`. Для локального цифрового выхода действие `set_pin` принимает имя выхода и `1` либо `0`. Для сервопривода предусмотрено `set_servo` с численным углом. Сложные формулы угла из старых руководств не поддерживаются полноценным вычислением. Диапазоны и дополнительные типы действий требуют отдельной проверки в выбранном способе настройки; не переносите старые примеры автоматически.

`rule_list` показывает список, `rule_info <id>` — настройку, `rule_states` — состояния. Команда `rule_enable <id> off` приостанавливает правило без удаления.

## Два порога вместо частого переключения

Предположим, условие включения срабатывает при температуре выше 28, а выключения — ниже 26. Между порогами состояние не меняется от небольших колебаний показаний. Такой разнос порогов называется гистерезисом.

Числа приведены для объяснения и не являются агрономическими рекомендациями. Два правила должны управлять одним устройством согласованно. Проверьте исходное состояние при запуске и поведение, когда свежие данные больше не приходят.

## Периодические задачи

`task_wizard` открывает мастер; `task_list` показывает задачи. Пауза и возобновление доступны через `task_disable <id>` и `task_enable <id>`.

Интервал задаёт повторение во времени работы устройства. Это не гарантирует исполнение по календарной дате или местному времени. После перезапуска нужно проверить момент первого выполнения.

## Алгоритмы

Используйте `algo_wizard`, затем `algo_list` и `algo_info <id>`. Алгоритм предназначен для сочетания условий и последовательности действий с задержками и повторениями.

Проверяйте каждый шаг сначала вручную. Команда `algo_test` может запускать действия, поэтому её используют только на подготовленном стенде. Вложенные и многовходовые сценарии, а также их перенос из приложений, не следует считать подтверждёнными только по наличию редактора.

## Ручное управление и связь

Ручная команда может временно иметь преимущество перед обычным правилом. Защитное состояние также может блокировать действие с меньшим приоритетом. Если выход не меняется, проверьте состояние устройства и журнал, а не повторяйте команды непрерывно.

Удалённое правило зависит от доставки свежих данных и команды. Выберите безопасное поведение при их отсутствии и проверьте его на стенде. Текущие улучшения защиты ожидают аппаратных испытаний. [Готовность](project-status.md).
