# Несколько ESP32: связь и удалённые устройства

[Главная](README.md) · [Обзор системы](01_Architecture_and_Design.md) · [Команды](06_CLI_Reference.md)

## Для чего нужна сеть

Одна плата может измерять показатель, другая — управлять устройством рядом с механизмом. Связь позволяет передать показание или команду без прокладки сигнального кабеля между этими точками. Локальные правила остаются на своих узлах.

В текущей разработке используется AgriSwarmMesh с ESP-NOW. Понятие Mesh здесь описывает сетевую часть проекта; произвольная многошаговая маршрутизация, масштаб и дальность не заявлены как подтверждённые характеристики.

## Четыре понятия

| Термин | Простое объяснение |
|---|---|
| Узел / Node ID | Плата и её адрес в сети. |
| Устройство / Device ID | Конкретный датчик или выход на плате. |
| Тема / topic | Имя потока данных или управления. |
| Подписка | Настройка получения данных определённого удалённого устройства. |

Обнаружение платы не означает автоматическое подключение всех её датчиков к каждому правилу. Подписка и источник правила должны соответствовать друг другу.

## Первый опыт с двумя платами

1. Установите совместимую версию на обе платы и убедитесь, что локальные устройства работают по отдельности.
2. Разместите платы рядом, задайте совместимые сетевые параметры через предусмотренную настройку.
3. Посмотрите `node_list` на каждой плате.
4. Проверьте `topics_tree`, запишите ID нужного датчика и узла.
5. На принимающей плате настройте подписку, подставив реальные идентификаторы:

```text
topics_manage subscribe <nodeId> <deviceId> sensor
topics_subscriptions
```

6. Измените реальное показание и проверьте, что принимающий узел получает обновление.
7. Только после этого добавляйте правило и удалённое действие.

Источник удалённого правила должен совпадать с публикуемым идентификатором или темой, которые показывает ваша настройка. Одинаковое краткое имя на двух платах не следует считать однозначным адресом.

## Что происходит при ошибке доставки

Для надёжного пути команд актуаторов предусмотрены ограниченные повторы и подтверждение результата. Повторный пакет может быть распознан и не исполнен заново в пределах сохранённой истории получателя. Старые версии и другие типы сообщений могут работать иначе.

Подтверждение означает результат обработки команды получателем, а не доказательство физического движения механизма. Для контроля механики нужен соответствующий датчик обратной связи. При полном обрыве связь не сможет доставить даже подтверждение.

## Потеря источника

Удалённое правило перестаёт получать новые данные при отключении источника. Для управляемого устройства нужно заранее определить безопасное состояние и проверить поведение при потере связи. Текущие изменения этого механизма собраны, но требуют проверки на двух ESP32.

## Размещение

После опыта рядом перенесите платы в реальные места и повторите проверку. Учитывайте металлические корпуса, стены, мокрую растительность, помехи и качество питания. Число узлов и расстояние выбираются по результатам проверки конкретного стенда.
